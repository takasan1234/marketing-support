# version-differ スキル

## 目的

同じフレームワークの2バージョンを比較し、サブ要素ごとに「追加・削除・変更された内容」を構造化して要約する。単純なテキスト差分ではなく、意味のある変化を識別する。

## 処理手順

1. **入力の確認**
   - `projectId`: 対象プロジェクトID
   - `frameworkType`: フレームワーク種類（例: `SWOT`）
   - `v1`: 比較元バージョン番号（古い方）
   - `v2`: 比較先バージョン番号（新しい方）

2. **両バージョンのデータ取得**
   ```bash
   npx tsx .claude/scripts/load-framework.ts <projectId> <frameworkType> --version <v1>
   npx tsx .claude/scripts/load-framework.ts <projectId> <frameworkType> --version <v2>
   ```

3. **差分分析**
   各サブ要素（`data` オブジェクトのキー）について:
   - **追加**: v1 に存在しないが v2 に追加された項目
   - **削除**: v1 に存在したが v2 から削除された項目
   - **変更**: 両バージョンに存在するが内容が異なる項目
   - **同一**: 変更なしの項目

   **意味的判断の指針**:
   - 表現が変わっても趣旨が同じ場合は「微修正」と分類
   - 追加情報が付いた場合は「拡張」と分類
   - 方向性が反転した場合は「変更（重要）」と分類
   - 複数の項目が統合/分割された場合は「再構成」と分類

4. **ノート比較**
   v1 と v2 の `note` フィールドを比較し、記録された更新意図を抽出する。

5. **差分サマリー出力**
   以下の形式でレポートを生成:

```
<frameworkType> バージョン差分レポート
比較: v<v1>（<v1作成日>）→ v<v2>（<v2作成日>）

■ 更新ノート:
  v<v1>: <note内容>
  v<v2>: <note内容>

■ サブ要素別差分:

[<サブ要素名>]
  変更種別: <追加 / 削除 / 変更 / 微修正 / 拡張 / 変更(重要) / 再構成 / 変更なし>
  v<v1>: <旧内容の要約>
  v<v2>: <新内容の要約>
  変化の概要: <1〜2文の自然言語説明>

■ 変更サマリー:
  - 変更されたサブ要素: X件
  - 追加されたサブ要素: X件
  - 削除されたサブ要素: X件
  - 変更なし: X件

■ 全体的な変化の解釈:
  <フレームワーク全体としてどのような観点が変化したか、2〜4文で要約>
```

## 例

### 呼び出し例
```
SWOT v1 と v2 の差分を見せて。プロジェクトID: proj_abc123
```

### 出力例
```
SWOT バージョン差分レポート
比較: v1（2024-01-15）→ v2（2024-03-20）

■ 更新ノート:
  v1: 初版
  v2: 競合分析更新後に再評価

■ サブ要素別差分:

[strength]
  変更種別: 拡張
  v1: 技術力、ブランド認知度
  v2: 技術力、ブランド認知度、特許ポートフォリオ（3件）
  変化の概要: 知的財産の強みが新たに認識・追加された。

[threat]
  変更種別: 変更(重要)
  v1: 市場競争激化
  v2: 新規参入者（海外大手2社）による価格競争圧力
  変化の概要: 脅威の内容が抽象から具体的な競合情報に更新された。

■ 変更サマリー:
  - 変更されたサブ要素: 2件
  - 追加されたサブ要素: 0件
  - 削除されたサブ要素: 0件
  - 変更なし: 2件
```

## エラー時の対応

- **バージョンが存在しない**: 利用可能なバージョン一覧を表示する
- **v1 と v2 が同じ**: 同じバージョンを比較しようとしていることを通知する
- **データ形式が異なる**: フレームワーク種類によってサブ要素構造が異なる場合があることを説明し、可能な範囲で比較する
