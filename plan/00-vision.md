# 00. ビジョン

## 解決したい課題

マーケティングのフレームワークを使うとき、以下の3つの「迷子」が発生する：

1. **入力の迷子**：フレームワークを開いたが、何を書けばいいか分からない。「強み」「機会」と言われても、どの情報を見て、どう考えればいいか分からない。
2. **データの迷子**：手元にデータはあるが、どのフレームワークで整理すべきか分からない。あるいは、そのフレームワークの埋め方には合っていない。
3. **構造の迷子**：フレームワーク同士の関係（前段の出力が次段の入力になる）が見えず、抜け漏れが発生する。

## 中核的価値

> **フレームワークを埋めるとき、「どの生データ・どの前段分析を参照すればいいか」が常に見えるシステム。**
> フィードバックを受けてサイクルを回せる（前回バージョンとの差分を保持）。

## 中心となる概念

### 2種類のデータ
- **生データ**：市場統計、ユーザーインタビュー、競合情報など、フレームワークの「材料」となる情報
- **フレームワーク出力**：PEST 分析の結果、SWOT の結果など、整理された分析結果

### 4層構造
1. **層① 生データ層**：12種類、各種類ごとに有効期間（TTL）あり、バージョン管理
2. **層② サブ要素⇔生データの紐付け**：定義として保持
3. **層③ サブ要素レベルの上流参照**：例：3C+C.Customer は PEST + 整理軸を参照
4. **層④ フレームワーク間の依存グラフ**：PDF の「分析結果の活用方法」記述から構築

## 使い方の典型シナリオ

### 新規プロジェクト立ち上げ
1. プロジェクト作成「SaaS スタートアップ X」
2. 全フレームワーク一覧を確認（依存グラフ表示）
3. PEST / 5Forces / VRIO / 整理軸 から着手（依存の出発点）
4. Claude Code に「PEST.Politics を埋める情報を集めて」と依頼
5. 生データが揃ったら手動編集で清書
6. SWOT → STP → 4P へ進む

### サイクル運用
1. プロダクトを出してフィードバックを得た
2. 「販売実績」「顧客調査」を生データに追加
3. 古い生データの一部に「鮮度切れ」警告
4. SWOT v2 を作成（v1 を残しつつ、変更点を見られる）
5. STP / 4P も連動して更新

## 何を「作らないか」

- **AI による自動分析**：生成 AI による「指摘」「自動評価」は不要（ユーザ自身が考えるためのツール）
- **未入力の警告**：入力強制はしない
- **観光特化**：DMO 関連の特化機能は実装しない（汎用化）
- **クラウド連携**：完全ローカル
- **モバイル対応**：デスクトップブラウザ前提
